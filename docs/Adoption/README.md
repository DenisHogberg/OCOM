# Adoption

**Document ID:** ADOPTION-README-01

**Status:** Informative

**Version:** 0.1

---

## What This Is

The Adoption Framework is a guided on-ramp into OCOM. It exists because the full specification — Core, Governance, and the Specification reading path — is written for precision, not for a first encounter. This section is written for a first encounter.

It introduces no new concepts, changes no definitions, and adds no requirements. Everything here is a restatement, in a more approachable order, of what `Core/`, `Meta/`, `Models/`, and `docs/Specification/` already say. Where something here is a simplification, it says so and points to the normative source.

## Who This Is For

Someone who has not yet read the specification and wants to know, in about half an hour: what OCOM actually is, whether it solves a problem they have, and what a first, small use of it would look like. That could be an engineer, an architect, or someone deciding whether to invest a team's time in it.

If you have already read `docs/Specification/00 Executive Overview.md` through `08 Conformance.md`, this section will mostly repeat what you know, in a more casual voice.

## How to Read These Documents

1. **[Getting Started](Getting%20Started.md)** — what OCOM is, the minimal set of concepts, and how to model your first Object and Lifecycle.
2. **[First Pilot](First%20Pilot.md)** — how to run a small, bounded first attempt, without Enterprise-scale ambition.
3. **[FAQ](FAQ.md)** — direct answers to the questions people usually ask before starting.
4. **[Common Mistakes](Common%20Mistakes.md)** — what tends to go wrong early, and why.

After these, the next step is `docs/Specification/01 Introduction.md` — the actual entry point to the normative specification.
