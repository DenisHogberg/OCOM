# Published Files With No Other Source

`ocom.uno` is generated by a Publication Engine that lives outside this repository and is no
longer available (`docs/Governance/Publication-Model.md`, Known Gaps). Most of what the site
serves can still be traced: a term-card is generated from a `Meta/` document, the Specification
pages are compiled from `docs/Specification/`, the Observatory records are recomputed by
`tools/site/publication_health.py`. A few files can not. They are hand-maintained on the server,
they state facts about the specification, machines read them, and nothing here says what they
should contain. This directory is where those files get a source.

The rule is the plain one: the file served at the published path shall be byte-for-byte identical
to the file named here, and the copy here is the one to edit. A served file that drifts from its
source is a published claim no reader can check against a reviewed text, which is the condition
this directory exists to end.

| Published path | Canonical source | Why it is here |
|----------------|------------------|----------------|
| `https://ocom.uno/llms.txt` | `publication/llms.txt` | States the specification's identity, status, licences, author, DOI and entry points to any machine that reads the site. Written by hand, generated from nothing. |

`tools/site/published_source_parity.py` fetches each published path and compares it with its
source. It is deliberately not a CI job, for the same reason `publication_health.py` is not: a
check that fetches the live site makes the build depend on the site being reachable. Run it after
a deploy, and before trusting a claim this directory makes.

Adding a file here is not a way to publish something new. A file belongs in this directory only
once the site already serves it and nothing else in this repository can reproduce it.
